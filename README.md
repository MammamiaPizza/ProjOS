## 1. เครื่องมือนี้ทำอะไรได้

shell ธรรมดาและคำสั่ง `history` ทำไม่ได้ แต่เครื่องมือนี้ทำได้:

| สิ่งที่ shell ธรรมดาขาด | สิ่งที่เครื่องมือนี้เพิ่มให้ |
|---|---|
| ไม่เก็บ exit code | ✅ บันทึก exit code ทุกครั้งที่รัน |
| ไม่จับเวลา | ✅ จับเวลาระดับมิลลิวินาที |
| ไม่วัดทรัพยากร | ✅ วัดเวลา CPU (user/sys) และหน่วยความจำสูงสุดต่อคำสั่ง |
| เปรียบเทียบการรันซ้ำไม่ได้ | ✅ `replay` แสดงผลต่างจากการรันครั้งก่อน |
| คำสั่งค้างทำให้ติดขัด | ✅ `timeout` ฆ่าคำสั่งที่รันนานเกินกำหนด |
| ล้มเหลวชั่วคราวต้องกดรันเอง | ✅ `retry` รันซ้ำให้อัตโนมัติ |
| ไม่มีสถิติ | ✅ `stats` บอกคำสั่งที่ช้า / ใช้บ่อย / พังบ่อย / **flaky** |

**flaky** คือคำสั่งที่เคยสำเร็จและเคยล้มเหลวปนกันในประวัติ — บ่งชี้ว่าผลลัพธ์ไม่น่าเชื่อถือ

## 3. วิธี Build และรัน

> ⚠️ **โค้ดนี้เป็น POSIX ล้วน** ใช้ `fork`, `execvp`, `wait4`, `setpgid`, `pipe`, `dup2`,
> `termios`, `alarm` — **build บน Windows แท้ ๆ / MinGW ไม่ได้**
> ต้องเข้าไปใน WSL ก่อนเสมอ และ `make` ไม่มีอยู่ฝั่ง Windows

### ขั้นตอนที่ 1 — เปิด PowerShell แล้วเข้า WSL

```powershell
wsl -d Ubuntu
```

prompt จะเปลี่ยนเป็น `pizza@LaptopOfPizza:~$`
**ต้องใส่ `-d Ubuntu` เสมอ** เพราะ distro เริ่มต้นอาจเป็น `docker-desktop` ซึ่งไม่มี shell ให้ใช้

### ขั้นตอนที่ 2 — ไปที่โฟลเดอร์โปรเจกต์

```bash
cd /mnt/d/Code/OS_Tet/proj
```

### ขั้นตอนที่ 3 — Build

```bash
make
```

จะได้ข้อความ `Build complete: ./history_tool` และ **ต้องไม่มี warning เลย**

ถ้าเครื่องไม่มี `make` ใช้คำสั่งตรงแทน:

```bash
gcc -O2 -Wall -Wextra -std=c99 command_history_tool.c -o history_tool
```

### ขั้นตอนที่ 4 — รันโปรแกรม

```bash
./history_tool
```

จะเห็น prompt เป็น `[linux] ~/proj>` — **พิมพ์คำสั่งลงที่นี่ ไม่ใช่ใน PowerShell**

### ขั้นตอนที่ 5 — ออกจากโปรแกรม

```
exit
```

### Make target ที่มีให้

| คำสั่ง | ทำอะไร |
|---|---|
| `make` | compile เป็น `./history_tool` |
| `make run` | compile แล้วเปิดโปรแกรมเลย |
| `make test` | รัน smoke test แบบไม่ interactive |
| `make clean` | ลบ binary, `history.log`, `history.csv`, `out.txt` |

> `make test` ใช้วิธี pipe ข้อความเข้าโปรแกรม โปรแกรมจะตรวจพบ `!isatty()` แล้วอ่านด้วย
> `fgets()` แทน line editor — ทำให้ทดสอบอัตโนมัติได้ แต่แปลว่า **`make test` ทดสอบปุ่มลูกศร,
> Tab และ Ctrl+C ไม่ได้** ต้องกดเองในเทอร์มินัลจริง

## 4. สองโหมดการทำงาน

สลับได้ทุกเมื่อด้วยคำสั่ง `mode` ไม่ต้องรีสตาร์ท

| โหมด | ใครเป็นคนประมวลผลบรรทัด |
|---|---|
| `linux` (ค่าเริ่มต้น) | **ตัวโปรแกรมเอง** แยกคำแล้วเรียก `fork` / `execvp` / `pipe` / `dup2` |
| `shell` | ส่งบรรทัดให้ `sh -c` — glob และ `$VARS` จะทำงาน |

```
[linux] ~/proj> echo *.c
*.c                              <- เป็นข้อความตรง ๆ ไม่ขยาย glob
[linux] ~/proj> echo $HOME
$HOME                            <- ไม่ขยายตัวแปร

[linux] ~/proj> mode shell
[shell] ~/proj> echo *.c
command_history_tool.c           <- sh ขยาย glob ให้แล้ว
[shell] ~/proj> echo $HOME
/home/pizza
```

**prompt บอกโหมดปัจจุบันเสมอ** — `[linux]` หรือ `[shell]`

พิมพ์ `mode` เฉย ๆ (ไม่มีอาร์กิวเมนต์) เพื่อดูว่าตอนนี้อยู่โหมดไหน

> **แนะนำให้อยู่โหมด `linux` ตอนพรีเซนต์** เพราะเป็นโหมดที่แสดงให้เห็น system calls จริง ๆ
> โหมด `shell` มีไว้แสดงเปรียบเทียบว่าอะไรคือสิ่งที่เครื่องมือทำเอง อะไรคือสิ่งที่ shell ทำให้

**โหมด shell ไม่ได้ทำให้ฟีเจอร์หายไป** — `history`, `stats`, `replay`, `edit`, `search`, `retry`,
`timeout`, `export`, `cd`, `!!`, `help` ยังใช้ได้ครบ เพราะถูกตรวจก่อนส่งเข้า shell
และยังจับเวลา/วัดหน่วยความจำเหมือนเดิม เพราะ shell mode ถูกทำให้เป็น pipeline ขั้นเดียว
(`sh -c <บรรทัด>`) ใช้โค้ดชุดเดียวกันทั้งหมด

## 5. คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `<คำสั่งใด ๆ>` | รันแล้วบันทึกพฤติกรรมของมัน |
| `cmd1 \| cmd2` | pipeline (โหมด linux) |
| `cmd > f`, `cmd >> f`, `cmd < f` | redirection (โหมด linux) |
| `!!` | รันคำสั่งก่อนหน้าซ้ำ |
| `cd <dir>` | เปลี่ยนไดเรกทอรี — ต้องเป็น built-in เพราะ `chdir()` ในลูกจะหายไปตามลูก |
| `pwd` | แสดงไดเรกทอรีปัจจุบัน |
| `history` | แสดงประวัติทั้งหมด |
| `history --failed` | แสดงเฉพาะคำสั่งที่ล้มเหลว |
| `history --slow` | แสดง 10 คำสั่งที่ช้าที่สุด |
| `replay <id>` | รันคำสั่งเดิมซ้ำ แล้วเทียบกับการรันครั้งก่อน |
| `edit <id>` | ดึงคำสั่งเก่ามาวางบน prompt **โดยไม่รัน** เพื่อแก้ให้ถูกแล้วค่อยกด Enter |
| `retry <n> <cmd>` | รันสูงสุด n ครั้ง หยุดทันทีที่สำเร็จ |
| `timeout <sec> <cmd>` | ฆ่าคำสั่งถ้ารันเกิน sec วินาที |
| `search <keyword>` | ค้นหาคำสั่งที่มีคำนี้ |
| `stats` | สรุปสถิติ: ใช้บ่อยสุด / ช้าสุด / กินแรมสุด / อัตราล้มเหลว / flaky |
| `export <file.csv>` | เขียนประวัติทั้งหมดเป็น CSV |
| `mode [linux\|shell]` | ดูหรือสลับโหมด |
| `help` | แสดงรายการคำสั่ง |
| `exit` | ออก |

**built-in ทุกตัวเรียกได้โดยไม่ต้องใส่อาร์กิวเมนต์** — พิมพ์ `replay` เฉย ๆ จะได้ข้อความบอกวิธีใช้
ไม่ใช่ error ว่า `replay: command not found`

## 6. ปุ่มกดสำหรับแก้ไขบรรทัด

เครื่องมือมี line editor เขียนเองด้วย `termios` raw mode (ไม่ใช้ GNU readline)

| ปุ่ม | ทำอะไร |
|---|---|
| `↑` / `↓` | เรียกคำสั่งก่อนหน้า / ถัดไป |
| `←` / `→` | เลื่อนเคอร์เซอร์ในบรรทัด |
| `Home` / `End` | ไปต้นบรรทัด / ท้ายบรรทัด (หรือ `Ctrl-A` / `Ctrl-E`) |
| `Tab` | เติมชื่อคำสั่งให้เต็ม (คำแรก) หรือเติมชื่อไฟล์ (คำถัดไป) |
| `Backspace` / `Delete` | ลบตัวอักษรหลัง / หน้าเคอร์เซอร์ |
| `Ctrl-K` | ลบจากเคอร์เซอร์จนถึงท้ายบรรทัด |
| `Ctrl-L` | ล้างหน้าจอแล้ววาดบรรทัดใหม่ |
| `Ctrl-C` | ที่ prompt: ทิ้งบรรทัดปัจจุบัน / ตอนคำสั่งกำลังรัน: ฆ่าคำสั่งนั้น |
| `Ctrl-D` | ออก ถ้าบรรทัดว่าง |

**Tab ทำงานอย่างไร:**
- คำแรก → ค้นหาใน `PATH` แล้วตรวจ `access(X_OK)` ว่าเป็นโปรแกรมที่รันได้จริง
- คำอื่น → อ่านชื่อไฟล์ในไดเรกทอรีด้วย `opendir` / `readdir`
- ถ้ามีหลายตัวเลือก → เติมเฉพาะส่วนที่เหมือนกันที่สุด (longest common prefix) แล้วโชว์รายการทั้งหมด
- ถ้าเติมแล้วเป็นไดเรกทอรี → ใส่ `/` ต่อท้ายให้อัตโนมัติ
- รายการที่แสดงถูกจำกัดไว้ที่ 64 รายการ เพราะบน WSL ค่า `PATH` มีไฟล์จาก System32 ปนอยู่เป็นพัน

## 7. ตัวอย่างการใช้งานจริง

```
[linux] ~/proj> echo hello
hello
[Done] exit=0 wall=5.64ms cpu=4.51/0.00ms mem=7188KB

[linux] ~/proj> ls | wc -l
5
[Done] exit=0 wall=8.33ms cpu=7.83/2.52ms mem=8016KB

[linux] ~/proj> foobar123
foobar123: command not found
[Done] exit=127 wall=121.62ms cpu=0.00/12.04ms mem=996KB

[linux] ~/proj> timeout 2 sleep 10
[Timed out] exit=124 wall=2001.12ms cpu=4.65/0.00ms mem=7816KB

[linux] ~/proj> replay 1
[Replaying #1] echo hello
hello
[Done] exit=0 wall=5.14ms cpu=0.00/4.86ms mem=7568KB

--- diff vs run #1 ---
exit code : 0 -> 0  (unchanged)
wall time : 6ms -> 5ms  (-7.5%)
cpu u/s   : 0/4ms -> 0/5ms
peak mem  : 7220KB -> 7568KB

[linux] ~/proj> edit 3
[Loaded #3 - edit it and press Enter]
[linux] ~/proj> gcc -O2 main.c -o app -Wall
                                       ↑ เคอร์เซอร์อยู่ตรงนี้ ยังไม่ได้รันอะไร
                                       แก้เสร็จแล้วค่อยกด Enter

[linux] ~/proj> stats
=== Command Statistics ===
Total commands   : 15
Distinct commands: 5
Most used        : "echo" (6 times)
Slowest          : "sleep 10" (2001 ms)
Highest memory   : "sleep 10" (7816 KB)
Failure rate     : 40% (6/15)

Flaky commands (both passed and failed):
  ! "sh" (passed 2, failed 1)
```

### ความหมายของบรรทัดสรุป

```
[Done] exit=0 wall=5.64ms cpu=4.51/0.00ms mem=7188KB
        │      │            │       │        └─ หน่วยความจำสูงสุด (max RSS)
        │      │            │       └─ เวลา CPU ใน kernel (system time)
        │      │            └─ เวลา CPU ใน user space
        │      └─ เวลาจริงที่ผ่านไป (wall clock)
        └─ exit code
```

**wall กับ cpu ต่างกันยังไง:**
- `sleep 2` → wall ≈ 2000ms แต่ cpu ≈ 0ms เพราะรอเฉย ๆ ไม่ได้ใช้ CPU
- `grep -r pattern /dirใหญ่` → wall สูง cpu ต่ำกว่า เพราะติด disk I/O
- ถ้า cpu ≈ wall → คำสั่งนั้น CPU-bound จริง ๆ

### ลำดับการสาธิต (สำหรับพรีเซนต์)

1. `ls`, `echo hello` → โชว์บรรทัดสรุปต่อคำสั่ง
2. `ls | wc -l` และ `echo hi > out.txt` → พิสูจน์ว่าทำงานเหมือน shell จริง
3. `foobar123` → "command not found", บันทึก exit `127`
4. `sleep 30` แล้วกด Ctrl+C → คำสั่งตาย แต่เครื่องมือยังอยู่, บันทึก exit `130`
5. `timeout 2 sleep 30` → ถูกฆ่าอัตโนมัติ, บันทึก exit `124`
6. `timeout 2 sh -c "sleep 30 & sleep 30 & wait"` → ตาย **ยกทั้ง process group**
7. รันคำสั่งหนัก ๆ (เช่น compile) → โชว์เวลา CPU และแรมจริง
8. `replay <id>` → โชว์ผลต่างจากการรันครั้งก่อน
9. `edit <id>` → ดึงคำสั่งที่พิมพ์ผิดมาวางบน prompt แก้ให้ถูก **โดยที่ยังไม่รัน**
10. `retry 3 false` → ลอง 3 ครั้ง แล้วรายงานความล้มเหลว
11. `stats` → ช้าสุด / ใช้บ่อยสุด / อัตราล้มเหลว / flaky
12. `mode shell` → `echo *.c` ขยายglob; `mode linux` → ไม่ขยาย
13. ปุ่มลูกศร, `Home`/`End`, `Tab`, `Ctrl-K`, `Ctrl-L`
14. `export report.csv` → เปิดดูใน spreadsheet
15. `exit` แล้วเปิดใหม่ → ประวัติยังอยู่ครบ

## 8. ไฟล์ history.log

ข้อความธรรมดา บรรทัดละ 1 รายการ คั่นด้วย `|` โดยวาง **คำสั่งไว้ท้ายสุด**
เพื่อให้ตัวคำสั่งเองมี `|` อยู่ได้

```
id|timestamp|wall_ms|exit_code|user_ms|sys_ms|max_rss_kb|command
1|1791429312|4.94|0|0.00|3.78|7236|echo hello
2|1791429312|121.62|127|0.00|12.04|996|foobar123
3|1791429313|8.33|0|7.83|2.52|8016|ls | wc -l
```

> บรรทัดที่ 3 มี **9 ฟิลด์** ไม่ใช่ 8 — เพราะ `ls | wc -l` มี `|` อยู่ในคำสั่ง
> **นี่เป็นเรื่องถูกต้องและจงใจทำ** ตัว parser จะแยก `|` เพียง 7 ตัวแรก
> แล้วถือว่าส่วนที่เหลือทั้งหมดคือข้อความคำสั่ง
> นี่คือเหตุผลที่ต้องวางคำสั่งไว้ท้ายสุด — ไม่อย่างนั้น pipeline จะพังทุกครั้งที่โหลดประวัติ

### ความหมายของแต่ละฟิลด์

| ฟิลด์ | มาจากไหน |
|---|---|
| `timestamp` | `time(NULL)` |
| `wall_ms` | ผลต่างจาก `clock_gettime(CLOCK_MONOTONIC)` |
| `exit_code` | `WEXITSTATUS` — `124` = timeout, `127` = หาโปรแกรมไม่เจอ, `130` = ถูก Ctrl+C |
| `user_ms`, `sys_ms`, `max_rss_kb` | `struct rusage` จาก `wait4()` |
| `command` | บรรทัดคำสั่งดิบ |

**กรณี pipeline:** `exit_code` คือของขั้น **สุดท้าย** (ตามธรรมเนียม shell), เวลา CPU **รวม** ทุกขั้น,
`max_rss_kb` คือค่า **สูงสุด**

### export เป็น CSV

```
export report.csv
```

ได้ไฟล์ที่ Excel / Google Sheets เปิดได้ทันที มี header และครอบเครื่องหมายคำพูดให้ถูกต้อง
(ถ้าในคำสั่งมี `"` จะถูก escape เป็น `""` ตามมาตรฐาน CSV)

> `export` เขียนไฟล์ตามที่อยู่ที่ให้มา **เทียบกับไดเรกทอรีปัจจุบัน**
> ต่างจาก `history.log` ที่ถูกยึดเป็น absolute path (อ่านเหตุผลในข้อ 9)

## 9. ข้อจำกัดที่ควรรู้

| ข้อจำกัด | ทางออก |
|---|---|
| **โหมด linux ไม่ขยาย glob และ `$VAR`** | ใช้ `mode shell` — นี่คือเหตุผลที่มีโหมดนี้ |
| **ไม่รองรับ shell scripting** — ไม่มี `if` / `for`, ไม่มีตัวแปร, ไม่มี `&&` / `\|\|`, ไม่มี `;` | ถ้าจำเป็นต้องใช้ ให้สลับไป `mode shell` |
| **`edit` ใช้ได้เฉพาะตอนรันในเทอร์มินัลจริง** | ถ้า stdin เป็น pipe จะไม่มีตัวแก้ไขบรรทัดให้วางข้อความ — เครื่องมือบอกตรง ๆ ว่า `edit: needs an interactive terminal` ไม่เงียบหายไปเฉย ๆ |
| **`timeout` บันทึกคำสั่งที่รัน ไม่ใช่ตัว wrapper** | `timeout 2 sleep 10` ถูกบันทึกเป็น `sleep 10` — ดังนั้น `replay` รายการนั้นจะรันใหม่ **โดยไม่มี timeout** |
| **ไม่รองรับคำสั่งหลายบรรทัด** | 1 บรรทัด = 1 คำสั่ง |
| **กด Escape เฉย ๆ จะหน่วงเล็กน้อย** | เครื่องมือรอ 50ms ด้วย `select()` เพื่อแยกว่าเป็น Escape เดี่ยวหรือเป็นลูกศร — เป็นพฤติกรรมที่ตั้งใจ |

`;` ที่อยู่ **ในเครื่องหมายคำพูด** ใช้ได้ปกติ เพราะถูกส่งต่อไปให้โปรแกรมเอง

**ทำไม `history.log` ต้องเป็น absolute path:**
ถ้าเก็บเป็นชื่อ relative (`history.log`) ทุกครั้งที่ผู้ใช้ `cd` ไปโฟลเดอร์อื่น
โปรแกรมจะไปสร้างไฟล์ประวัติใหม่ในโฟลเดอร์นั้นแทน — ประวัติจะกระจายหายไปทีละน้อยโดยไม่มีใครรู้
จึงต้องแปลงเป็น absolute path **ครั้งเดียวตอนเริ่มโปรแกรม ก่อนจะมีคำสั่งใดรันได้**

## 10. แก้ปัญหาเบื้องต้น

### `make : The term 'make' is not recognized...`

**คุณกำลังอยู่ใน PowerShell ไม่ใช่ WSL** — `make` ไม่มีฝั่ง Windows
แก้โดยรัน `wsl -d Ubuntu` ก่อน แล้วค่อย `cd /mnt/d/Code/OS_Tet/proj`

### `execvpe(bash) failed`

distro เริ่มต้นของคุณคือ `docker-desktop` ซึ่งไม่มี shell
**ต้องใส่ `-d Ubuntu` ทุกครั้ง:** `wsl -d Ubuntu`

### `Makefile:21: *** missing separator`

เกิดจาก 2 สาเหตุ:
1. ไฟล์ Makefile เป็น CRLF — แก้ด้วย `sed -i 's/\r$//' Makefile`
2. ใช้ heredoc ใน recipe — Make อ่านทีละบรรทัด จึงเข้าใจผิดว่าเป็น rule
   ให้ใช้ `printf '...\n...' | ./$(TARGET)` แทน

### `make: Nothing to be done for 'all'`

ไม่ใช่ error — แปลว่า binary ใหม่กว่า source แล้ว ไม่ต้อง compile ใหม่
ถ้าอยากบังคับให้ build ใหม่: `make clean && make`

### กดลูกศรแล้วไม่ทำงาน

- ตรวจสอบว่าคุณกำลังใช้เทอร์มินัลจริง ไม่ใช่การ pipe ข้อความเข้าโปรแกรม
- ถ้า stdin ไม่ใช่ terminal โปรแกรมจะเลิกใช้ line editor โดยอัตโนมัติ (ออกแบบไว้เช่นนั้น)

### ประวัติหายไป

- ตรวจว่า `history.log` เขียนได้: `ls -la history.log`
- ประวัติอยู่ไฟล์เดียวเสมอ ไม่ว่าคุณจะ `cd` ไปที่ไหน

### คำสั่งหาไม่เจอ

- โปรแกรมค้นหาใน `PATH` เหมือน shell ปกติ
- ตรวจว่าโปรแกรมนั้นติดตั้งอยู่และอยู่ใน `PATH`
